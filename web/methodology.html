How Mastered measures

public-signal · v1

Mastered exists because the AI-capability ecosystem has massive supply and almost no honest signal. So the first rule is: we measure what people actually run, from public evidence — and we show our work. Here is exactly what we count, how the ranking is computed, and what we deliberately refuse to do.

No user tracking. Mastered installs nothing, instruments no one, and reads no private data. Every number on this site is derived from public GitHub and is re-derivable by anyone.

What we count (V1)

We mine public GitHub for the files where people declare the capabilities they actually use — mcp.json, claude_desktop_config.json, and .cursor MCP configs — and extract each declared server. From that sample we measure:

  • Reach — distinct owners who wired the capability into a real config. Owner-level, so one person's fifty repos count once. This is the hardest signal to fake and the one we rank on.
  • Repos — distinct public repositories referencing it in the sample.
  • Host quality — the star distribution (median / max) of the repos that use it. Are serious projects reaching for it, or only throwaways?
  • Freshness — the most recent push of a host repo. Is it living in active code, or in repos that went quiet a year ago?
  • Co-use — which capabilities get configured alongside it. The shape of real stacks.

The Mastered Signal

The single Index number is deliberately simple and public — no black box:

Signal = round( 100 × ln(1 + reach) ÷ ln(1 + reachmax) )

It's owner-reach, log-normalized to the most-adopted capability in the sample. Log scale so a handful of giants don't flatten everything below them; owner-based so a spammed monorepo can't buy rank. That's it. When we add retention and evals (below), they'll be shown as separate, labelled scores — never quietly blended into one number you can't inspect.

What we deliberately don't do

  • We don't count stars. Stars measure hype and are trivially farmed. A 20k-star "awesome list" tells you nothing about whether a capability works.
  • We don't count downloads. A download is curiosity; keeping something in your config is a decision.
  • We don't take pay-to-rank. There is no promoted slot, no boost, no ad in the Index — now or ever.
  • We don't launder reviews. Self-reported "5 stars" is the failure mode of every store that came before us.
  • We don't re-list registries and call it usage. A directory entry is supply. We measure demand.

What this is not (yet) — stated plainly

  • It's a sample, not a census. GitHub code search is rate-limited and indexes only public default branches, so absolute counts are directional. Relative ranking is the signal.
  • Adoption is not quality. Popular ≠ good. Reach tells you what people chose, not whether it served them well. That gap is exactly what the roadmap closes.
  • Private, enterprise, and non-GitHub usage is invisible to V1.

The roadmap — trust as an output of evidence

  • Retention & churn — from git history: which capabilities get added then removed, and what replaced them. Removal is the most honest review there is.
  • Controlled evals — reproducible benchmarks we run ourselves, so "it works" is measured, not claimed.
  • Compatibility — which models and environments a capability actually works in.
  • Cost — token/latency footprint on load and per call.

Each of those is a separate, defensible measurement. Stacked, they become something no directory can copy: an evidence base for what actually works.
