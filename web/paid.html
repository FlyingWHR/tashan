Payment is not an input to the tashan score. “Someone pays for this” and “this is well made” are different claims — the top earner here scores 71.

We are in this table. Tashan CLI publishes a price and has settled $0.00, ever. An instrument that exempts itself from its own measurement is not an instrument.

What this does not mean

  • Charging is not being paid. A service can publish a price and never settle a single call. Both facts are on this page and they are different columns.
  • Unpaid is not bad. Almost every MCP server is free by design; an absent row here says nothing about quality. It says nobody has paid this address, because nobody was asked to.
  • Volume belongs to an address, not to a project. Where one payment address is shared by several services the chain cannot separate them, so those receipts are counted in the totals above and never attributed to a capability. 11 matched receivers are excluded from the table for exactly that reason.
  • This is Base, and x402 only. Other chains, other payment rails and private billing are invisible here. We publish what is on the ledger we can read.

Re-run it yourself

Two Graph products, composed: a subgraph on The Graph Network, read through The Graph’s Subgraph MCP server. Point any MCP client at it and you get the same rows.

https://subgraphs.mcp.thegraph.com/sse
tool: execute_query_by_subgraph_id
subgraph_id: Cb56epg3EvQ6JRpPfknbkM54QxpzTvLa7mwKNQQfUyoj

{ x402AddressSummaries(first: 1000, where: {role: RECIPIENT}) {
address totalPayments totalVolume } }

From a clone of the repo, one command runs exactly that hop:

GRAPH_API_KEY=<your key> python3 pipeline/subgraph_mcp.py --probe

Addresses from the Bazaar’s own listings. Receipts from the chain. The join is an exact host match against a homepage or repository we already hold — never a fuzzy name match.
