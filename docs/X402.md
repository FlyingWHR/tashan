# Turning on pay-per-request (x402)

**Status: built, tested, and dormant.** Everything below the wallet is done. Turning it on is
setting four values; no code changes, no deploy of new logic.

This is the one thing in the agent-payment work that needs a human, because it means creating an
account that holds money. That is a CEO decision, not something to improvise inside a deploy.

---

## What is already true

`POST /v0.1/audit` is live and earning nothing yet, on purpose:

- **Free, no account, no payment:** every risk we hold about every capability a caller names —
  advisories at the version they would install today, deprecation, archived repos, single
  maintainer, registry removal — plus a `keep` / `review` / `replace` verdict. This is the part
  that must never be gated, and a test fails if it ever is.
- **Paid:** the score series behind each row and its direction of travel. Today that is reachable
  with a licence key. With a wallet it is also reachable per call.

`/api/history` and `/api/security` behave the same way, because the change went into `deny()` —
the single place every paid endpoint refuses.

Right now, every 402 quotes the subscription and the free endpoints. It carries **no** `accepts`
array and **no** `PAYMENT-REQUIRED` header, because we cannot settle a payment. Quoting a payment
option we cannot verify is worse than quoting none: the agent burns a signature and gets nothing.

---

## The decision

Three things, and only the first is really a decision:

1. **A wallet address we control.** This receives the money. I did not create one and will not —
   it is an account that holds funds.
2. **A network.** Base mainnet (`eip155:8453`) is where x402 traffic actually is. Base Sepolia
   (`eip155:84532`) is the testnet — worth one afternoon first, since a wrong `payTo` on mainnet is
   money sent somewhere else.
3. **A facilitator.** The service that verifies and settles. Coinbase runs one; the protocol lets
   anyone run one, including us, but running our own is a project and using theirs is a URL.

The asset is USDC on the chosen network — that is what the ecosystem prices in, and our amounts are
already in 6-decimal atomic units to match.

---

## Turning it on

Four secrets on the Pages project (`tashan`):

```sh
npx wrangler@3 pages secret put X402_PAY_TO      --project-name tashan   # 0x… address you control
npx wrangler@3 pages secret put X402_NETWORK     --project-name tashan   # eip155:8453  (or 84532 to test)
npx wrangler@3 pages secret put X402_ASSET       --project-name tashan   # USDC contract on that network
npx wrangler@3 pages secret put X402_FACILITATOR --project-name tashan   # https://…  (no trailing slash needed)
```

**All four or nothing.** `configured()` requires every one of them; three out of four stays dormant
rather than half-quoting a price. That is deliberate — see `functions/api/_x402.js`.

## Verifying it worked

```sh
curl -s -i -X POST https://tashan.sh/v0.1/audit \
  -H 'content-type: application/json' \
  -d '{"servers":["chrome-devtools-mcp"],"history":true}' | head -20
```

Before: `402` with `plans` and `free_result`, no `accepts`.
After: the same, **plus** `x402Version: 2`, an `accepts` array carrying your `payTo`, and a
`PAYMENT-REQUIRED` header. The free audit is still in the body either way.

Then test a real payment on Sepolia with any x402 client before pointing it at mainnet.

## What it prices

| resource | price | why that number |
|---|---|---|
| `config-audit` (`POST /v0.1/audit`) | $0.05 | The flagship. An agent hands us a whole config; this is the answer no static index can give. |
| `capability-history` (`/api/history`) | $0.01 | One capability's series. |
| `security-detail` (`/api/security`) | $0.01 | One capability's full advisory detail. |

Prices live in `PRICED` in `functions/api/_x402.js`, in dollars and atomic units side by side, with
a test asserting the two agree. Change them there and nowhere else.

These are guesses about what an agent will pay, and they are guesses we can correct: the nightly
funnel report (`pipeline/funnel.py`) counts what gets clicked, and nothing about the subscription
changes if per-call pricing moves.

---

## What it does not change

- **The firewall.** Nobody pays to change a score, a rank, or a listing. x402 buys access to
  measurements, exactly like a licence does, and `tests/test_firewall.py` still governs the scorer.
- **The free tier.** Every risk stays free on every surface, including this one. An audit that hides
  a known vulnerability behind a paywall is not an instrument.
- **Subscriptions.** A 402 quotes both: `plans` for people, `accepts` for software. Two ways to pay,
  not a replacement — and a *refused* licence is a 403 that is never downgraded to an x402 quote,
  because to a paying customer that reads as their subscription being ignored.

## Where the code is

| file | what it does |
|---|---|
| `functions/api/_x402.js` | Protocol layer: prices, PaymentRequired, verify → work → settle. Fails closed at every step. |
| `functions/api/_x402.test.mjs` | 39 checks, incl. every refusal path. No network, no credentials. |
| `functions/v0.1/audit.js` | The product. Free risk audit always; history is the paid half. |
| `functions/v0.1/audit.test.mjs` | 33 checks. Sabotage-verified: leaking history, hiding advisories, and serving after a failed settlement all fail. |
| `functions/api/_license.js` | `deny()` — carries the x402 quote when configured, unchanged when not. |

Implemented against `specs/x402-specification-v2.md` and `specs/transports-v2/{http,mcp}.md` from
`github.com/coinbase/x402`, read directly. v1's `maxAmountRequired` / `X-PAYMENT` are a different
generation and a test asserts we do not emit those names.
